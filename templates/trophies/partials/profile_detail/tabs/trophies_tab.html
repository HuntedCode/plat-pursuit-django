{% comment %} The Trophies tab: ONE surface whose shape follows intent -- rebuilt 2026-08. A search field over a wall of DAYS. With nothing in it you browse the history; searching swaps the wall for the matching trophies. There is no Activity/Log switcher, because those were never two ways of browsing: Activity is how you read a history, and the Log was an INDEX dressed as a wall. A single trophy has no natural shape -- an icon, a name, a percentage -- which is why no layout for it read well. As search results it does not need one. The toolbar is the site's, not a bespoke one: `.pp-toolbar-card` for the surface, `.pp-bgal__search` for the field, `.pp-bgal__chip` for the chips. `data-browse-form` hands it to `browse-filters.js`, which supplies Enter-to-submit, debounced live search, Escape-to-clear, the clear button and the in-flight spinner -- but only for markup that opts into them, which a hand-rolled field does not. {% endcomment %}
/ {% comment %}Tier is the one axis of a trophy that is both obvious to ask for and free to filter -- a column on Trophy, not a computed grade. CHECKBOXES, so several can be on at once: "their golds and platinums" is one question, and asking it as two searches is what a filter exists to avoid. They also toggle OFF by clicking, which radios cannot -- so the only thing Clear has to do is reset everything at once. Inside the shared chip, so `:has(input:checked)` drives the active state straight off the DOM and the control works with JS off; `browse-filters.js` auto-submits any checkbox change.{% endcomment %}
