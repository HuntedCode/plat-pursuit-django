{% comment %}One row of a tier list, or one slot of a grid. RENDERED IDENTICALLY FOR READER AND AUTHOR, with the controls added. The row IS the published artefact -- its label, its colour, its place in the order -- so an author editing it must be looking at what a respondent will see. `can_edit_rows` comes from `prompt_service.frozen_acts`, so a published grid draws no controls here and a draft draws them all, without this file knowing either rule. THE COLOUR IS A PALETTE SLOT, never free hex: `data-pd-colour` names the slot and the CSS maps it to a `--pp-*` derived colour, so a theme change moves every tier row at once and no UGC value can paint unreadable text over the design tokens. THE DRAG HANDLE IS NOT THE WHOLE ROW. A row carries a text input for the author; making the row itself draggable would eat the pointer events that input needs, which is the bug the list page's arrange mode records. The handle is its own control and carries the keyboard alternative with it.{% endcomment %}
