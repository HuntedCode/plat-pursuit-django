IT REPLACED A LINEAR RAIL (owner, 2026-10-08: it "doesn't really do a great job of explaining what you get at the various milestones"). The rail drew five pips and five numbers and never said what a number was worth. Each rung now names its title and its state, so the header answers "what do I get, and when" without the tutorial. FIVE EQUAL CELLS, each filling across its own span (see `calendar_render.marker_rail`), because the linear rail put the 50 and 100 rungs about 40px apart on a phone, with no room for a title beside either. ONE MARKUP, TWO LAYOUTS: a row of five columns from `md:`, where each cell's bar joins the next into one segmented track; a list on a phone, where five columns of ~58px cannot hold "Calendar Chronicler" at the 12px floor. On the phone a state glyph leads each row, and only the CURRENT rung keeps its bar, the one whose span the run is in. That is usually the next rung, but not on a second run below 50 days, where the first rung is already held and the next one's span has not started. THE FILE AND CONTEXT KEY KEEP THE RAIL'S NAME (`calendar_rail`): the ceremony reads the same dict, and a rename would touch every reader for no change in behaviour. The BLOCK is `.pp-cal-ladder`. "ALREADY YOURS" ONLY TO THE OWNER: the page is public, and a visitor reading a stranger's run is told "Already held" instead -- the second-person rule the opening ceremony's gate follows. THE COMPARISON FIGURE stays as a quiet footnote: `in_all` is the same days without the shovelware exclusion, which is what makes the count mean something read aloud. {% endcomment %}
