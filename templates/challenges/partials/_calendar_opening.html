{% comment %}THE PLAT CALENDAR'S OPENING CEREMONY: "here is where you stand", once per run. WHY IT EXISTS AT ALL. Every other challenge type starts empty and fills as a hunter plays. A Calendar run backfills their ENTIRE platinum history the moment it is created, so a veteran opens one already standing on two or three rungs of a five-rung ladder. Without a beat for that, the single most dramatic thing this feature does happens silently between a form POST and a redirect. PER RUN, NOT PER USER, which is why it is gated on `Challenge.opening_seen_at` rather than on a `CustomUser.ui_flags` key like every other one-shot on the site. A hunter can finish or hide a Calendar run and start another, and the second backfills again -- so this belongs to the run being opened. GATED SERVER-SIDE. `DetailModal` reads `data-auto` off this element, so the decision not to show it is made in the view; a script deciding would risk a flash of somebody else's progress. The view's gate is owner + not-yet-seen, and the owner part matters because a run page is public: "here is where YOU stand" shown to a visitor is a stranger's progress addressed in the second person. IT USES THE HOUSE MOLD AND THE HOUSE CONTROLLER. `.pp-detail-modal` is the shell the day sheet and the career explainer already wear, and `PlatPursuit.DetailModal` is the behaviour -- auto-open once, focus restore, Escape, and an `onDismiss` that records. Nothing here is a new primitive. IN `fixed_overlays`, for the reason the day modal records: `takeover` and the recede effect scale `#page-recede`, and a `position: fixed` element inside a transformed ancestor resolves against that ancestor rather than the viewport.{% endcomment %} {% comment %}NO BARE BLOCK CLASS. `.pp-calopen` would carry no rule of its own -- the element classes do the styling and the closing animation is keyed on the ID, joining the shared `#...is-closing` list in `series-list.css` -- and a class with no rule is what `test_every_class_reaches_the_compiled_bundle` exists to catch.{% endcomment %}
